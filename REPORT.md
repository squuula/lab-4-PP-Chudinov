# Отчёт по лабораторной работе №4. Ансамбли и полносвязные нейронные сети

Задача — бинарная классификация кредитоспособности клиента на датасете `german.csv`
(German Credit). Целевая переменная `Creditability`: 1 — «хороший» заёмщик (положительный
класс), 0 — «плохой».

## Данные и подготовка

- **Размер:** 1000 строк, 20 признаков + целевая переменная. Разделитель в CSV — `;`.
- **Баланс классов:** 700 «хороших» (1) и 300 «плохих» (0), то есть 70/30. Из-за дисбаланса
  accuracy сама по себе малоинформативна (константа «всегда 1» даёт 0.70), поэтому основная
  метрика — ROC-AUC по вероятностям.
- **Пропуски:** отсутствуют (проверено `df.isna().sum()`), импутация не нужна.
- **Split:** `train_test_split(test_size=0.3, stratify=y, random_state=42)` → 700 train / 300 test.
  Стратификация сохраняет долю классов 70/30 в обеих частях.
- **Типы признаков.** Все признаки закодированы числами, но по смыслу делятся на две группы:
  - категориальные (номинальные/ступенчатые коды): `Account_Balance`,
    `Payment_Status_of_Previous_Credit`, `Purpose`, `Value_Savings_Stocks`,
    `Length_of_current_employment`, `Sex_Marital_Status`, `Guarantors`,
    `Most_valuable_available_asset`, `Concurrent_Credits`, `Type_of_apartment`, `Occupation`;
  - числовые/порядковые: `Duration_of_Credit_monthly`, `Credit_Amount`, `Instalment_per_cent`,
    `Duration_in_Current_address`, `Age_years`, `No_of_Credits_at_this_Bank`, `No_of_dependents`,
    а также бинарные `Telephone`, `Foreign_Worker`.
- **Собственные признаки** (функция `add_features`, считаются построчно, без target):
  - `log_amount = log(1 + Credit_Amount)` — сумма кредита сильно скошена вправо;
  - `monthly_payment = Credit_Amount / Duration` — примерный ежемесячный платёж;
  - `log_monthly_payment` — его логарифм;
  - `burden = Instalment_per_cent * monthly_payment` — грубая оценка долговой нагрузки;
  - `no_account = [Account_Balance == 4]` — отсутствие текущего счёта (по EDA самый «хороший» сегмент).
- **Преобразования по типам моделей:**
  - деревья (RF, GB, AdaBoost, HGB) получают исходные числовые коды + новые признаки, без
    масштабирования: деревья инвариантны к монотонным преобразованиям;
  - MLP, логистическая регрессия и ExtraTrees: категориальные признаки → `OneHotEncoder`,
    остальные → `StandardScaler` (для MLP/LogReg). Для нейросети это обязательно: градиентный
    спуск плохо работает на признаках разного масштаба, а числовые коды категорий навязывают
    ложный порядок.
- Все преобразования находятся внутри `Pipeline`, поэтому `fit` трансформеров происходит только на
  train (внутри CV — только на обучающих фолдах), утечки из test нет.

## Гипотезы и эксперименты

**Протокол выбора.** Каждая модель оценивалась по среднему ROC-AUC на
`RepeatedStratifiedKFold(n_splits=5, n_repeats=3)` **только на train-части** (15 фолдов).
Test использовался лишь для итоговых метрик в таблице, а не для выбора модели или параметров.

Гипотезы и что проверялось:

1. **Baseline (E0).** Логистическая регрессия с one-hot — простая линейная точка отсчёта, чтобы
   понимать, дают ли ансамбли выигрыш.
2. **Random Forest (E1 → E2).** Бэггинг деревьев снижает дисперсию отдельного дерева. Гипотеза:
   на маленьком датасете полезно ограничить глубину листьев (`min_samples_leaf`), уменьшить
   корреляцию деревьев (`max_features`) и учесть дисбаланс (`class_weight="balanced_subsample"`).
   Сетка (`tuning.py`): `min_samples_leaf ∈ {1, 3, 5}`, `max_features ∈ {sqrt, 0.3, 0.5}`.
   Лучшее — `leaf=3, sqrt` (CV 0.7832), но различия в пределах ~0.005.
3. **Extra Trees (E3).** Ещё более случайные разбиения → ещё меньше дисперсии. Гипотеза не
   подтвердилась: CV 0.7575, хуже RF — на 700 объектах случайные пороги дают слишком «шумные» деревья.
4. **AdaBoost (E4).** Последовательное перевзвешивание ошибок. Худший результат (CV 0.7459):
   бустинг чувствителен к шуму в метках, а в German Credit таких «трудных» объектов много.
5. **Gradient Boosting (E5).** Сетка: `max_depth ∈ {2, 3}`, пары `(learning_rate, n_estimators)` ∈
   `{(0.03, 300), (0.05, 200), (0.01, 600)}`, `subsample=0.8` (стохастический бустинг как
   регуляризация). Лучшее — `depth=3, lr=0.03, 300 деревьев` (CV 0.7814).
6. **HistGradientBoosting (E6).** Быстрая версия бустинга с гистограммами. На 1000 строк выигрыша
   в скорости почти нет, качество чуть ниже GB (CV 0.7689).
7. **Полносвязная MLP (E7 → E8).** Гипотеза: данных мало, поэтому нужна маленькая сеть и сильная
   L2-регуляризация. Сетка: `hidden_layer_sizes ∈ {(8,), (16,), (32,), (16, 8)}`,
   `alpha ∈ {1, 3, 10}`. При `alpha=1` сеть переобучается (CV 0.757 для (32,)), лучшее —
   один скрытый слой из 16 нейронов, `alpha=3` (CV 0.7778). Двухслойная сеть стабильно хуже.
8. **Ансамбли разных моделей (E9–E11).** Главная гипотеза: RF (бэггинг), GB (бустинг) и MLP
   (гладкая нелинейная модель на one-hot) ошибаются по-разному, поэтому усреднение их
   вероятностей уменьшит дисперсию. Проверены:
   - Soft Voting RF + GB;
   - Stacking RF + GB + MLP с логистической регрессией в качестве мета-модели
     (мета-признаки — out-of-fold вероятности, внутренний 5-fold CV);
   - Soft Voting RF + GB + MLP (простое среднее вероятностей).

## Метрики

**Критерий выбора:** максимальный средний ROC-AUC на CV 5×3 по train. Метрики test — при пороге 0.5,
положительный класс 1. Все числа взяты из прогона `python experiments.py` (сохранены в
`experiment_results.json`).

нельзя, поэтому выбор сделан по CV.

## Выбранная модель

**Soft Voting (RandomForest + GradientBoosting + MLP)** — `VotingClassifier(voting="soft")`,
итоговая вероятность класса 1 — среднее вероятностей трёх моделей:

- `RandomForestClassifier(n_estimators=500, min_samples_leaf=3, max_features="sqrt",
  class_weight="balanced_subsample")` на исходных + сконструированных признаках;
- `GradientBoostingClassifier(n_estimators=300, learning_rate=0.03, max_depth=3, subsample=0.8)`
  на тех же признаках;
- `MLPClassifier(hidden_layer_sizes=(16,), alpha=3.0, max_iter=3000)` после one-hot +
  StandardScaler.

Почему именно она:

1. Лучший средний ROC-AUC на CV по train (0.7924) — это и есть заранее выбранный критерий.
2. Она стабильнее одиночных моделей: разброс по фолдам (±0.045) меньше, чем у RF (±0.056) и GB
   (±0.049).
3. Stacking (E10) дал почти то же качество (0.7902), но в ~5 раз дольше обучается (внутренний CV)
   и имеет дополнительную мета-модель, которую тоже можно переобучить на 700 объектах. Простое
   усреднение — более надёжный выбор при таком объёме данных.
4. Время одного запуска `run_ensemble_experiment` — около 2 секунд на CPU.

Итог на test (300 объектов): **ROC-AUC = 0.8286**, accuracy = 0.797, precision = 0.817,
recall = 0.914, F1 = 0.863.

## Выводы и ограничения

**Что улучшило результат:**
- регуляризация под маленький датасет: `min_samples_leaf=3` в RF, `subsample=0.8` и малый
  `learning_rate` в GB, `alpha=3` и маленький скрытый слой в MLP;
- `class_weight="balanced_subsample"` в RF — учёт дисбаланса классов;
- сконструированные признаки (логарифм суммы, ежемесячный платёж, нагрузка) — RF с ними и
  настройками стал лучше по CV (0.7769 → 0.7833);
- **объединение разнородных моделей**: каждая модель отдельно даёт CV ≤ 0.7833, а их среднее —
  0.7924. Выигрыш от ансамбля появляется именно потому, что модели разных типов делают разные ошибки.

**Что ухудшило / не сработало:**
- ExtraTrees и AdaBoost — хуже даже логистической регрессии;
- MLP с маленькой регуляризацией (`alpha=1`) и двухслойная MLP переобучаются;
- HistGradientBoosting не дал преимущества перед обычным GB на таком маленьком датасете.

**Ограничения:**
- Данных мало (1000 строк, из них 300 в test), поэтому оценка на одном test шумная: 1 объект
  меняет accuracy на 0.33 п.п. Для проверки устойчивости выбранная модель (уже после выбора, без
  влияния на него) была прогнана на 10 других случайных стратифицированных разбиениях 70/30:
  ROC-AUC = 0.810 ± 0.022 (min 0.774, max 0.849). То есть на «неудачном» разбиении качество может
  опуститься ниже 0.80.
- Порог 0.5 не подбирался: при дисбалансе 70/30 модель почти всех относит к «хорошим»
  (recall 0.91, но «плохих» заёмщиков пропускает чаще). В реальном кредитном скоринге ошибка
  «выдать кредит плохому заёмщику» дороже, и порог стоило бы подбирать по матрице стоимостей
  (на отдельной валидационной части train, а не на test).
- Подбор гиперпараметров — небольшие ручные сетки, а не полный перебор; разница между
  соседними точками сетки в пределах разброса CV.
- Признак `Sex_Marital_Status` использован как есть; в реальной системе его применение может
  быть ограничено требованиями к недискриминации.

## Воспроизводимость

- **Random seed:** 42 — в `train_test_split`, `RepeatedStratifiedKFold`, а также `random_state`
  у RF, GB и MLP (в функции берётся из `EnsembleInput.random_seed`, по умолчанию 42).
- **Split:** стратифицированный 70/30, `random_state=42` (700 train / 300 test).
- **Окружение:** Python 3, scikit-learn 1.9.1, pandas 3.0.5, numpy 2.5.3.
- **Как повторить:**
  ```bash
  python tuning.py        # предварительный подбор параметров RF/GB/MLP (≈3 мин)
  python experiments.py   # все эксперименты E0–E11 + experiment_results.json (≈6 мин)
  ```
  Финальная модель обучается и оценивается через контрактную функцию
  `run_ensemble_experiment` из `ensemble_models.py` (≈2 с на CPU). Повторный запуск с теми же
  данными и seed даёт те же вероятности и метрики.
